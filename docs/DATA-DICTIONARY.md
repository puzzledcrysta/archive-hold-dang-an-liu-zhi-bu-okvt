# 档案留置簿数据字典

## 来源文件

| 字段 | 定义 |
|---|---|
| 档案件 | 文本主键，保留前导零。跨业务键不汇并记录。 |
| 修订号 | 正整数。最高版优先；最高同版字段冲突或存在同版、更新版的未采信记录时隔离，旧版无法接替。 |
| 提交时间 | ISO 8601，必须带 UTC 偏移量。标准化后展示 UTC。 |
| 原始备注 | 可空，允许引号内换行。 |
| 结案日、查询日、保管政策、留置区段 | 必填字段。多项字段用半角分号隔开，显式空集合用 `无`。 |

识别 `UTF-8`、UTF-8 BOM 与独立的 `GB18030` 文件。`业务编号`、`版本`、`更新时刻`、`备注` 为旧版表头别名。新旧名同时出现会被拒绝。`-`、`N/A`、`NULL`、`未知` 和空串均按必填值缺失处理。物理行号指 CSV 逻辑记录起始行。

## 计算字段

政策写 `起始日期/结束日期/保管周年`，留置写 `开始日期/结束日期`，均为左闭右开。

闰日的周年落在非闰年时以 3 月 1 日计。处置日期遇到留置顺延到该段末端，续接留置继续顺延。

数值在服务端以十进制定点方式计算，对外按字符串传输。单文件上限 128 KiB，复合字段最多 240 个项目，个别字段还有业务上限。格式无法恢复的 CSV 整批拒绝，列数、缺字段、来源冲突和业务条件错误逐条隔离。

## 复算与外部清单

外部清单包含 `档案件` 和 `外部记录值(天)`，允许省略不在对账范围内的键。同一键重复会拒绝该清单。结果数值单位为 **天**。差值按本次复算减外部记录，缺一侧时差值计算以 0 占位并保留缺失原因。

同一对输入字节与规则版本生成同一批次，导出包含两个文件摘要、证据行、单边差异和复核修订记录。复核保存前检查当前版本，在有隔离、差异或退回时必须填写意见。

## 年限修订与可放行名单

修订文件表头固定为 `档案件,状态,保管政策`。`状态` 仅取 `已排期` 或 `复核中`，同一档案件在修订表中重复即整表拒绝，档案件必须能在来源有效记录中找到，否则按 `REVISION_KEY` 拒绝。

- `已排期`：旧清单仍按原年限，冻结其来源中的保管政策，按 `旧年限（原清单）` 评估，修订表中的新政策不对其生效。
- `复核中`：以修订表中的保管政策覆盖来源政策，按 `新年限（修订生效）` 在生效日重算；新政策无法命中唯一区间时整份名单不出（`REVISION_UNRESOLVED`）。
- 名单逐件写明 `policy_version`、`schedule_status`、最早处置日与查询判定。旧版放行集合与新版放行集合硬性互斥，相交即按 `ROSTER_CONFLICT` 拒绝，响应带 `exclusive` 标记。
- 名单指纹 = `sha256(规则版本:修订文件摘要:生效日)`。同一份修订与生效日重跑返回同一 `roster_id`，`created=false` 表示命中既有有效名单，不另建。
- 切换在单个 SQLite 事务内完成：先把当前有效名单备份进 `roster_history` 再替换 `active_roster`，任一步失败整体回滚，旧名单不被覆盖。每次切换备份其前一份有效名单，首份切换前无有效名单故无备份。
- `POST /api/release/rollback` 恢复最近一条备份：恢复即消费该备份（从历史删除），当前名单不回灌历史，因此不能无限来回回滚；无备份时以 `ROSTER_NO_BACKUP` 拒绝，绝不清空有效名单。
